# Oman EM Prep — بنك أسئلة اختبار الطوارئ (عُمان)

منصة تدريب للأطباء المستعدين لاختبار الطوارئ (Prometric / Oman Medical Specialty Board) — بنفس فكرة UWorld لكن أخف وأوضح.

**يقرأ بنكك الحقيقي كما هو** — 18 قسماً، 5,093 سؤالاً بصيغة الملفات الأصلية (`options` كائن حروف، `correct_answer` حرف أو فارغ) دون أي تعديل على ملفات البيانات.

## 2) تجربة الطبيب — نظام الدرجات

- **Exam Readiness %** (الرقم الرئيسي): متوسط إتقان البنك كله — "هل أنا جاهز؟"
- **كل سؤال له إتقان:** غير مُجاب = 0 · صحيح مرة = 50 · مرتين متتاليتين = 75 · **ثلاثاً متتاليتين = Mastered** — وأي إجابة خاطئة تصفّر السلسلة وتُعيد السؤال لقائمة المراجعة
- **أسئلة بلا إجابة محفوظة (850 سؤالاً):** تظهر بخيار "Show Explanation" ثم **تقييم ذاتي** (أجبت صح / أخطأت) — يدخل نفس نظام الدرجات
- **قائمة الأخطاء:** السؤال يخرج منها فقط بعد إجابتين صحيحتين متتاليتين
- **حفظ تلقائي للجلسة:** أغلق التبويب في منتصف الجلسة وستجدها في "Resume where you left off"
- **⚡ Cram Review:** بطاقات فلاش لأضعف أسئلتك (بلا سكور) — قبل ليلة الامتحان
- الأسئلة بلا إجابة محفوظة تُستثنى من الاختبارات المؤقتة (تحتاج تصحيحاً موضوعياً)

## 3) بنية التنقل (3 تبويبات)

- **🏠 الرئيسية** — "ماذا أفعل اليوم؟": شريط الجاهزية المضغوط، أكمل الجلسة، قائمة اليوم (3 اقتراحات مرتبة: راجع أخطاءك ← أكمل قسمك ← كرام)، شريط OEEM المختصر، آخر الجلسات
- **📚 التدريب** — الأقسام الـ18؛ النقر على قسم يفتح **صفحة القسم**: زر دراسة كبير + **3 فحوص تغطية** (تُفتح عند تغطية 25% / 50% / 75% من أسئلة القسم — 20 سؤالاً · 25 دقيقة · تسحب مما درسته فقط، وتعرض أفضل نتيجة) + تدريبات أخطاء القسم ومحفوظاته
- **🎓 الاختبارات** — محاكاة OEEM الشاملة (الأرصدة + الفتح) وسجل كل المحاولات (محاكاة + فحوص أقسام)

على الجوال يهبط شريط التبويب لأسفل الشاشة (نطاق الإبهام). أثناء أي اختبار يختفي شريط التبويبات (وضع التركيز).

## 5) صيغة السؤال المقبولة (كما هي في ملفاتك)

```json
{
  "id": 1,
  "source_format": "A",
  "subject": "Cardiology",
  "topic": null,
  "page": 4,
  "question": "…",
  "options": { "A": "…", "B": "…", "C": "…", "D": "…", "E": "…" },
  "correct_answer": "C",
  "correct_answer_text": "…",
  "explanation": "…",
  "has_image": false
}
```

يقبل التطبيق أيضاً: `options` كمصفوفة، `correct_answer` كرقم index، و`null` (تقييم ذاتي). رموز التحكم الناتجة عن استخراج PDF (`\u0003`…) تُنظَّف عند التحميل تلقائياً.

## 7) سلّم الاختبارات (نظام الفتح)

**🧩 اختبارات المحطات العشرة** — التقدم أثناء الرحلة:
- تُفتح بالتغطية الفريدة: الأول عند **500 سؤالاً** مغطى، ثم كل **300** (800، 1100، … 3200)
- المزيج: **75% من أسئلة غطّاها المستخدم فعلاً + 25% جديد "تشويقي"** — موزّعان بأوزان المخطط الرسمي (توزيع الباقي الأكبر يضمن النسبة عالمياً)
- 50 سؤالاً · 75 دقيقة · خط زمني ومؤشر وتيرة · مستكشف أسئلة · إعادة محاولة بأسئلة جديدة وأفضل درجة تُحفظ
- **العدّ الفريد**: تكرار نفس السؤال لا يزيد التغطية — من يكرر 100 سؤال عشرين مرة لا يفتح شيئاً
- النتائج تعرض **"Studied vs Fresh"**: دقتك في مادتك مقابل المادة الجديدة

**🎓 محاكاة OEEM الثلاث** — المقارنة الحقيقية:
- تُفتح بالتغطية: **80%** ثم **90%** ثم **98%** من البنك كله
- **ورقة ثابتة حرفياً**: سحب محسوم البذرة (seeded) من المخطط الرسمي — نفس الـ100 سؤال لكل مستخدم، جاهزة للوحة ترتيب عادلة عند إضافة الحسابات
- 100 سؤال · 150 دقيقة · تسليم تلقائي عند 0:00 · النتائج حسب مجالات المخطط مع وسم "focus here"

**المسار المقترح**: تبويب التدريب يعرض الأقسام مرتبة بأوزان المخطط الرسمي كسلسلة منارات — ترشيح لا إجبار؛ الاختبارات تتكيف مع أي مسار يختاره الطبيب.

كل العتبات والأحجام والمزائج والبذور في `data/blueprint.json` — بيانات قابلة للتعديل بلا لمس الكود.

## 8) الحسابات ورموز الدخول والمنصة الإدارية

- **الهوية**: الطبيب يسجل بحساب (اسم + بريد + واتساب + كلمة مرور) بلا رمز — تقدمه يتبعه على كل الأجهزة. السجلات محمية بـ RLS: كل طبيب يرى بياناته فقط
- **التجربة والدفع**: 15 سؤالاً مجاناً (تُعدّ من تقدّمه المحفوظ في الخادم) ← شاشة الدفع ببيانات التحويل التي تضبطها من تبويب Payment ← يرفع صورة الإيصال ← تقبله من تبويب Requests فيُفتح حسابه نهائياً. الرفض يحمل سبباً ويتيح إعادة الرفع
- **رموز الدخول**: مسار جانبي ما زال يعمل — تولّد دفعات من لوحة الإدارة (عدد + تسمية + أقصى استخدامات + صلاحية)، ويُدخلها الطبيب من شاشة الدفع
- **المزامنة**: التطبيق محلي أولاً (يعمل بلا إنترنت)؛ بعد الدخول يرفع تقدمه القديم ثم يزامن تلقائياً (كل 30 ثانية + بعد كل جلسة). تكرار نفس السؤال لا يضخم التقدم
- **المنصة الإدارية** (`admin.html`): نظرة عامة (الأطباء، النشطون 7 أيام، متوسط التغطية، الرموز المتبقية، نشاط 14 يوماً) · جدول الأطباء مع تنقيب لكل طبيب (أضعف أقسامه، جلساته) · إدارة الرموز
- **المدير**: أول حساب يُنشأ في المشروع يصبح admin تلقائياً (bootstrap)؛ صفحة الإدارة مقفولة على غيره

**التشغيل (دقيقتان):**
1. أنشئ مشروعاً مجانياً على supabase.com
2. SQL Editor → الصق `supabase/schema.sql` → Run، ثم `supabase/002_trial_paywall.sql` → Run (إضافي، لا يحذف بيانات)
3. Project Settings → API → انسخ Project URL و anon public key
4. الصقهما في `js/config.js` → أعد التحميل

الإعداد فارغ = **الوضع المحلي** (بلا حسابات، كما كان) — لا شيء ينكسر قبل الربط.

**تجربة التدفّق محلياً بلا مساس بالمشروع الحي:** `node tools/dev-server.js` ثم افتح `http://localhost:8000` — خادم يحاكي Supabase في الذاكرة (حسابات الاختبار مذكورة أعلى الملف).

## 9) خارطة الطريق

1. استخراج الصور الـ31 المرتبطة بأسئلة (`has_image: true`) من `bluebook.db` أو `bluebook-extracted.zip` وعرضها
2. تنظيف أعمق لنصوص استخراج PDF (مسافات مفقودة مثل "polymorphicventricular")
3. نشر على رابط عام + تجربة مع أطباء أخذوا الاختبار فعلاً وقياس الاستعداد للدفع
4. حسابات + دفع (Thawani / Stripe) على Supabase
5. لاحقاً: خطة مذاكرة بالتكرار المتباعد، واختبارات GCC أخرى بنفس المحرك
