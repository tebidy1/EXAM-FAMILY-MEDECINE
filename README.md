# Saudi Prep — النسخة السعودية من منصة التدريب

هذا المستودع نسخة **معزولة** من محرّك المنصة الأصل (المستودع المسجَّل هنا باسم `upstream` — انظر `git remote -v`): الكود نفسه، ببنك أسئلة مختلف وقاعدة بيانات مستقلة ونطاق مستقل. لا شيء هنا يقرأ من النسخة الأصل أو يكتب فيها.

- **ما يخص البلد في مكان واحد**: `js/edition.js` (الاسم، العملة، الأسعار المؤقتة، النصوص). أربعة ملفات ثابتة تكرر الاسم يدوياً: `index.html`، `admin.html`، `manifest.json`، `get/index.html`.
- **البنك الحالي عيّنة**: 4 أقسام × 20 سؤالاً، قُصّت من بنك النسخة الأصل بـ `tools/make_sample.js` لإثبات أن كل شيء يعمل. تُستبدل ببنكك الحقيقي — الطريقة في [`docs/content-guide.md`](docs/content-guide.md).
- **الفحص قبل أي نشر** (كلاهما يجب أن ينجح):

```bash
node tools/check_edition.js
```

```bash
node tools/validate_data.js
```

## 2) تجربة الطبيب — نظام الدرجات

- **Exam Readiness %** (الرقم الرئيسي): متوسط إتقان البنك كله — "هل أنا جاهز؟"
- **كل سؤال له إتقان:** غير مُجاب = 0 · صحيح مرة = 50 · مرتين متتاليتين = 75 · **ثلاثاً متتاليتين = Mastered** — وأي إجابة خاطئة تصفّر السلسلة وتُعيد السؤال لقائمة المراجعة
- **أسئلة بلا إجابة محفوظة:** تظهر بخيار "Show Explanation" ثم **تقييم ذاتي** (أجبت صح / أخطأت) — يدخل نفس نظام الدرجات
- **قائمة الأخطاء:** السؤال يخرج منها فقط بعد إجابتين صحيحتين متتاليتين
- **حفظ تلقائي للجلسة:** أغلق التبويب في منتصف الجلسة وستجدها في "Resume where you left off"
- **⚡ Cram Review:** بطاقات فلاش لأضعف أسئلتك (بلا سكور) — قبل ليلة الامتحان
- الأسئلة بلا إجابة محفوظة تُستثنى من الاختبارات المؤقتة (تحتاج تصحيحاً موضوعياً)

## 3) بنية التنقل (3 تبويبات)

- **الرئيسية** — "ماذا أفعل اليوم؟": لوحة الجاهزية (بأسلوب شاشة المؤشرات الحيوية)، ثم إجراء واحد واضح (أكمل الجلسة أو أول اقتراح اليوم)، ثم بقية الاقتراحات وهدف الاختبار التالي وآخر الجلسات
- **التدريب** — الأقسام في قائمة واحدة مرتبة بأوزان المخطط الرسمي، وحلقة إتقان لكل قسم؛ النقر على قسم يفتح **صفحة القسم**: زر دراسة كبير + **3 فحوص تغطية** (تُفتح عند تغطية 25% / 50% / 75% من أسئلة القسم — 20 سؤالاً · 25 دقيقة · تسحب مما درسته فقط، وتعرض أفضل نتيجة) + تدريبات أخطاء القسم ومحفوظاته
- **الاختبارات** — سلّم المحطات ومحاكاة الاختبار وسجل كل المحاولات

**التصميم موجّه للجوال أولاً**: شريط التبويب أسفل الشاشة (نطاق الإبهام)، وزر الإجراء الرئيسي في شاشة السؤال مثبت أسفلها. على التابلت والكمبيوتر يصعد شريط التبويب إلى الشريط العلوي ويبقى المحتوى في عمود واحد. أثناء أي اختبار يختفي شريط التبويبات (وضع التركيز). الحساب والمظهر (فاتح/داكن) والتثبيت وتسجيل الخروج في ورقة الحساب (الدائرة أعلى اليمين).

### التثبيت كتطبيق (PWA)

- `manifest.json` + `sw.js` + `icons/` تجعل الموقع قابلاً للتثبيت على الشاشة الرئيسية ويفتح بملء الشاشة
- **عرض التثبيت**: بطاقة في الرئيسية وبعد النتائج، رابط في شاشة الدخول، وصف في ورقة الحساب، وورقة تظهر مرة واحدة بعد أول 5 أسئلة. على Android/Chrome زر واحد يفتح نافذة التثبيت؛ على iPhone تظهر الخطوات الثلاث (مشاركة ← إضافة إلى الشاشة الرئيسية ← إضافة). "ليس الآن" يخفي العرض 14 يوماً
- **بلا اتصال**: بعد أول فتح تُحفظ الواجهة وبنك الأسئلة على الجهاز؛ التطبيق يفتح بلا إنترنت بآخر ملف شخصي محفوظ، والإجابات تُرفع عند عودة الاتصال
- **عند كل نشر**: ارفع رقم `?v=` في `index.html` و`admin.html` — الصفحة تُجلب من الشبكة أولاً فتلتقط الملفات الجديدة فوراً
- **الأيقونات**: `node tools/make-icons.js` يعيد توليد ملفات PNG (بلا مكتبات). الشعار نفسه مرسوم في `icons/icon.svg` وفي `LOGO` داخل `js/app.js`

### صفحة الهبوط `/get`

`get/index.html` صفحة هبوط إنجليزية للجوال توجَّه إليها الإعلانات:

- **الصفحة**: تعريف وثلاث حقائق وزر تثبيت واحد واضح لجهاز الزائر (يُكتشف تلقائياً، مع رابط للجهاز الآخر)، ثم «لماذا بنيناه»، خمس مزايا بلقطات حقيقية، خطوات البدء، طرق الاشتراك (بلا أسعار)، أسئلة شائعة، وزر التثبيت مرة أخيرة. شريط تثبيت ثابت أسفل الشاشة يظهر متى غاب الزر عن النظر
- **دليل iPhone** (`#iphone`): مشاركة ← إضافة إلى الشاشة الرئيسية ← إضافة ← الفتح، ثم نموذج التسجيل الحقيقي مرقّماً بترتيب تعبئته
- **دليل Android** (`#android`): الخطوات نفسها مختصرة، وفي آخرها زر «Install app» يفتح نافذة التثبيت مباشرة؛ إن لم يعرض المتصفح التثبيت بلمسة واحدة يُظهر الزر طريق القائمة ⋮ بالصور
- تستخدم `manifest.json` و`sw.js` نفسيهما، فالتثبيت منها يفتح التطبيق نفسه (`start_url` هو الجذر)
- من داخل متصفح إنستغرام/فيسبوك/تيك توك لا يمكن التثبيت: تظهر ملاحظة «افتح الصفحة في Safari/Chrome» مع زر نسخ الرابط. ومن يفتحها من التطبيق المثبَّت يُحوَّل إلى التطبيق
- صور الخطوات رسوم SVG في الملف نفسه؛ `get/*.jpg` لقطات حقيقية من التطبيق (`signup.jpg` نموذج التسجيل؛ `app-home.jpg` و`f-today.jpg` من هذه النسخة، وبقية لقطات الأسئلة موروثة). أعدها بعد دخول البنك الحقيقي

## 4) الأقسام

الأقسام في `data/sections.json` — كل قسم ملف من `data/questions/`، و`count` فيه يجب أن يطابق عدد أسئلة الملف (الفحص يرفض غير ذلك). البنك الحالي عيّنة: Medicine · Pediatrics · Surgery · OBGYN، عشرون سؤالاً لكل قسم.

## 5) صيغة السؤال المقبولة (كما هي في ملفاتك)

```json
{
  "id": 1,
  "source_format": "A",
  "subject": "Cardiology",
  "topic": null,
  "page": 4,
  "question": "…",
  "options": { "A": "…", "B": "…", "C": "…", "D": "…", "E": "…" },
  "correct_answer": "C",
  "correct_answer_text": "…",
  "explanation": "…",
  "has_image": false
}
```

يقبل التطبيق أيضاً: `options` كمصفوفة، `correct_answer` كرقم index، و`null` (تقييم ذاتي). رموز التحكم الناتجة عن استخراج PDF (`\u0003`…) تُنظَّف عند التحميل تلقائياً.

## 6) الفحص قبل النشر

```bash
node tools/validate_data.js
```

يفحص كل ملفات الأقسام: تكرار المعرّفات، نطاق الإجابات، نص الإجابة مقابل الخيار، أسئلة بلا شرح، وشوائب الاستخراج — ثم يطابق `count` في `sections.json` مع كل ملف، ويتأكد أن `blueprint.json` لا يسمّي قسماً غير موجود ولا يطلب اختباراً أكبر من البنك.

## 7) سلّم الاختبارات (نظام الفتح)

**🧩 اختبارات المحطات** — التقدم أثناء الرحلة:
- تُفتح بالتغطية الفريدة عند العتبات المكتوبة في `milestoneTests` (`unlockAt`)
- المزيج: **75% من أسئلة غطّاها المستخدم فعلاً + 25% جديد "تشويقي"** — موزّعان بأوزان المخطط
- خط زمني ومؤشر وتيرة · مستكشف أسئلة · إعادة محاولة بأسئلة جديدة وأفضل درجة تُحفظ
- **العدّ الفريد**: تكرار نفس السؤال لا يزيد التغطية
- النتائج تعرض **"Studied vs Fresh"**: دقتك في مادتك مقابل المادة الجديدة

**🎓 محاكاة الاختبار** — المقارنة الحقيقية:
- تُفتح بنسبة التغطية المكتوبة في `simulations` (`unlockAtCoverage`)
- **ورقة ثابتة حرفياً**: سحب محسوم البذرة (seeded) من المخطط — نفس الأسئلة لكل مستخدم
- تسليم تلقائي عند 0:00 · النتائج حسب مجالات المخطط مع وسم "focus here"
- اسم الاختبار على الواجهة يأتي من `exam.code`

**المسار المقترح**: قائمة الأقسام في تبويب التدريب مرتبة بأوزان المخطط الرسمي — ترشيح لا إجبار؛ الاختبارات تتكيف مع أي مسار يختاره الطبيب.

كل العتبات والأحجام والمزائج والبذور في `data/blueprint.json` — بيانات قابلة للتعديل بلا لمس الكود.

## 8) الحسابات ورموز الدخول والمنصة الإدارية

- **الهوية**: الطبيب يسجل بحساب (اسم + بريد + واتساب + كلمة مرور) بلا رمز — تقدمه يتبعه على كل الأجهزة. السجلات محمية بـ RLS: كل طبيب يرى بياناته فقط
- **التجربة والدفع**: 25 سؤالاً مجاناً (تُعدّ من تقدّمه المحفوظ في الخادم) ← شاشة الدفع ببيانات التحويل التي تضبطها من تبويب Payment ← يرفع صورة الإيصال ← تقبله من تبويب Requests فيُفتح حسابه نهائياً. الرفض يحمل سبباً ويتيح إعادة الرفع
- **رموز الدخول**: مسار جانبي ما زال يعمل — تولّد دفعات من لوحة الإدارة (عدد + تسمية + أقصى استخدامات + صلاحية)، ويُدخلها الطبيب من شاشة الدفع
- **البرومو الدعائي والدعوات (أسئلة مجانية إضافية)**: عملة أخف من الوصول الكامل — "أسئلة إضافية" تُضاف إلى سقف التجربة المجانية (`profiles.bonus_questions`) فيكمل الطبيب الدراسة مجاناً بعد أول 25، وكل الإعدادات من تبويب **Growth** في لوحة الإدارة:
  - **رموز برومو**: كل رمز يفتح عدداً من الأسئلة (تحدده عند الإنشاء) حتى أقصى استخدامات وصلاحية — للحملات الدعائية. يُدخله الطبيب من شاشة الدفع أو من ورقة الحساب ("لديك رمز دعائي؟")، ويُفتح الرصيد فوراً. رمز واحد لا يُستهلك مرتين من الحساب نفسه
  - **الدعوات (ريفيرال)**: لكل طبيب رابط دعوة خاص (`?ref=CODE`) في ورقة الحساب ("ادعُ زملاءك"). عند انضمام زميل عبر الرابط يُكافأ الداعي تلقائياً (مكافأة تسجيل)، وعند اشتراك ذلك الزميل يُكافأ مرة أخرى (مكافأة أكبر)، والزميل نفسه يبدأ بمكافأة ترحيب. الأرقام الثلاثة قابلة للضبط و0 يُعطّل المكافأة. كل الإضافة تجري في الخادم (triggers/RPC) تلقائياً دون أي خطوة من الطبيب
  - **ترتيب النشر آمن**: قبل تشغيل `supabase/004_promo_referral.sql` يخفي التطبيق مدخل الرمز الدعائي والدعوة ويعمل كما كان؛ بعد تشغيله يظهران تلقائياً (الدعوة تظهر فقط حين تُضبط مكافأة أكبر من 0 في تبويب Growth)
  - **عرض الانطلاق** (`supabase/005_launch_offer.sql`): يضبط مكافأة الداعي على 30 سؤالاً عند تسجيل الزميل و350 عند اشتراكه، وينشئ الرمز `START100` (45 سؤالاً إضافياً، لأول 100 حساب) — أي 70 سؤالاً مجانياً مع الـ25. الأرقام كلها تُعدَّل بعدها من تبويب Growth
  - **بلا تلاعب**: لا شيء يلمسه الطبيب يمنح أسئلة لنفسه — كل زيادة تمر عبر دوال `security definer` محمية بنفس حارس `app.access_rpc`
- **المزامنة**: التطبيق محلي أولاً (يعمل بلا إنترنت)؛ بعد الدخول يرفع تقدمه القديم ثم يزامن تلقائياً (كل 30 ثانية + بعد كل جلسة). تكرار نفس السؤال لا يضخم التقدم
- **المنصة الإدارية** (`admin.html`): نظرة عامة (الأطباء، النشطون 7 أيام، متوسط التغطية، الرموز المتبقية، نشاط 14 يوماً) · جدول الأطباء مع تنقيب لكل طبيب (أضعف أقسامه، جلساته، رصيده من الأسئلة الإضافية ودعواته) · إدارة الرموز · تبويب **Growth** (رموز البرومو + أرقام مكافآت الدعوة)
- **المدير**: أول حساب يُنشأ في المشروع يصبح admin تلقائياً (bootstrap)؛ صفحة الإدارة مقفولة على غيره

**التشغيل (دقيقتان):**
1. أنشئ مشروعاً مجانياً على supabase.com
2. SQL Editor → الصق `supabase/schema.sql` → Run، ثم بالترتيب `supabase/002_trial_paywall.sql` و`supabase/003_plans.sql` و`supabase/004_promo_referral.sql` و`supabase/005_launch_offer.sql` → Run (كلها إضافية، لا تحذف بيانات، وآمنة لإعادة التشغيل)
3. Project Settings → API → انسخ Project URL و anon public key
4. الصقهما في `js/config.js` → أعد التحميل

الإعداد فارغ = **الوضع المحلي** (بلا حسابات، كما كان) — لا شيء ينكسر قبل الربط.

**تجربة التدفّق محلياً بلا مساس بالمشروع الحي:** `node tools/dev-server.js` ثم افتح `http://localhost:8000` — خادم يحاكي Supabase في الذاكرة (حسابات الاختبار مذكورة أعلى الملف).

1. اسم الاختبار الحقيقي وصياغة الخطاب (الواجهة تخاطب «الطبيب») — مرور واحد على `js/edition.js` والصفحات الثابتة الأربع
