# دليل تجهيز بنك الأسئلة

هذا الدليل لمن يجهّز المحتوى، ولا يحتاج خبرة برمجية. المطلوب ثلاثة أشياء: ملف لكل مادة، ملف يسرد المواد، وملف يصف الاختبار. في مجلد [`content-template`](content-template) مثال جاهز لكل واحد منها، انسخه وعدّل عليه.

البنك الموجود الآن في `data/` عيّنة من 80 سؤالاً، وُضعت لتجربة المنصة فقط، وتُستبدل كلها بمحتواك.

## 1. ملف لكل مادة

كل مادة ملف واحد داخل `data/questions/`، اسمه بالإنجليزية بلا مسافات، مثل `Biology.json`. الملف قائمة أسئلة، وكل سؤال بهذا الشكل:

```json
{
  "id": 1001,
  "subject": "Biology",
  "topic": "Cell division",
  "question": "نص السؤال كاملاً…",
  "options": {
    "A": "الخيار الأول",
    "B": "الخيار الثاني",
    "C": "الخيار الثالث",
    "D": "الخيار الرابع"
  },
  "correct_answer": "B",
  "explanation": "لماذا B صحيحة، ولماذا البقية خاطئة…"
}
```

| الحقل | مطلوب؟ | ما هو |
|---|---|---|
| `id` | نعم | رقم السؤال. **يجب ألا يتكرر في البنك كله**، لا داخل المادة فقط. أسهل طريقة: كل مادة تأخذ ألفاً خاصاً بها (المادة الأولى 1001، 1002… والثانية 2001، 2002…). ولا تغيّر رقم سؤال بعد النشر: تقدّم الطلاب محفوظ على هذا الرقم. |
| `question` | نعم | نص السؤال. |
| `options` | نعم | من خيارين إلى ثمانية، بالحروف `A` `B` `C`… بالترتيب ودون قفز. |
| `correct_answer` | نعم | حرف الإجابة الصحيحة، مثل `"B"`. |
| `explanation` | نعم عملياً | الشرح الذي يظهر فور الإجابة. المنصة مبنية على الشرح: سؤال بلا شرح يُقبل لكن الفحص ينبّه عليه. |
| `subject` | لا | اسم المادة، يظهر سطراً صغيراً تحت الشرح. |
| `topic` | لا | الموضوع داخل المادة، يظهر بجانب اسم المادة. |

ملاحظات:

- النص يُكتب كما هو، بالعربية أو الإنجليزية. داخل النص استعمل `\n` لسطر جديد، واكتب علامة التنصيص هكذا `\"`.
- إن تركت `correct_answer` فارغة (`null`) يصبح السؤال «تقييماً ذاتياً»: يرى الطالب الشرح ثم يحدد هو هل أصاب. هذه الأسئلة لا تدخل الاختبارات المؤقتة، فلا تستعملها إلا مضطراً.
- الصور غير مدعومة حالياً. سؤال يعتمد على صورة لا يصلح قبل إضافة هذه الميزة.

## 2. ملف المواد `data/sections.json`

يسرد المواد التي تظهر في التطبيق، بالترتيب:

```json
{
  "sections": [
    {
      "id": "biology",
      "name": "Biology",
      "nameAr": "الأحياء",
      "icon": "🧬",
      "file": "data/questions/Biology.json",
      "count": 250
    }
  ]
}
```

- `id`: اسم قصير بحروف إنجليزية صغيرة وأرقام وشرطات فقط (`organic-chemistry`). لا يتغير بعد النشر.
- `name` و`nameAr`: الاسم كما يراه الطالب.
- `icon`: رمز تعبيري واحد.
- `file`: مسار ملف المادة.
- `count`: عدد أسئلة الملف **بالضبط**. إن أضفت أو حذفت سؤالاً عدّل هذا الرقم، والفحص يرفض أي فرق.

## 3. ملف الاختبار `data/blueprint.json`

يصف الاختبار الحقيقي حتى تبني المنصة اختباراتها على شاكلته:

- `exam`: اسم الاختبار (`code` هو الاسم المختصر الذي يظهر على الواجهة)، وعدد أسئلته ومدته بالدقائق.
- `domains`: مجالات الاختبار ووزن كل مجال، والمواد التي تغذّيه. مجموع الأوزان 100. كل اسم في `sections` يجب أن يكون `id` موجوداً في `sections.json`.
- `milestoneTests`: اختبارات مرحلية تُفتح كلما غطّى الطالب عدداً من الأسئلة (`unlockAt`)، وحجم كل اختبار (`size`) ومدته.
- `simulations`: المحاكاة الكاملة، تُفتح عند نسبة تغطية (`unlockAtCoverage`، و`0.8` تعني 80%). `seed` نص ثابت يجعل الورقة نفسها لكل الطلاب، فلا تغيّره بعد النشر.

لا يجوز أن يطلب اختبار أسئلة أكثر مما في البنك، والفحص يرفض ذلك.

إن لم تكن متأكداً من الأوزان، أرسل المواد وعدد أسئلة الاختبار الحقيقي ومدته، ويُكتب هذا الملف لك.

## 4. الفحص

بعد وضع الملفات في `data/` شغّل:

```bash
node tools/validate_data.js
```

- السطر الأخير `✔ Question bank is valid — safe to publish.` معناه أن البنك سليم.
- كل سطر يبدأ بـ `✗` خطأ يجب إصلاحه، ويذكر الملف ورقم السؤال والمشكلة. مثال: `data/questions/Biology.json#14 (1015): correct_answer "E" outside options range (4 options)` معناه أن السؤال رقم 1015 إجابته `E` وليس فيه إلا أربعة خيارات.
- كل سطر يبدأ بـ `⚠` تنبيه لا يمنع النشر، وأهمها سؤال بلا شرح.

## 5. التسليم

ضع ملفات المواد في `data/questions/`، واستبدل `data/sections.json` و`data/blueprint.json`، واحذف ملفات العيّنة الأربعة. أو أرسل الملفات كما هي، ويتم وضعها وفحصها ونشرها.

يمكن التسليم على دفعات: مادة واحدة مكتملة تكفي للنشر، والبقية تُضاف لاحقاً بإضافة ملفها وسطرها في `sections.json`.
